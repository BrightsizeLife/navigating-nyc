## What I changed (Tier 1)

**Security & Privacy**
- Removed the unused `html:` → `innerHTML` branch from the DOM builder `h()`
  (`docs/assets/app.js`). It had zero callers (verified by repo-wide grep and the
  71-check browser suite). innerHTML is how cross-site scripting happens: if a future
  edit had passed geocoder- or URL-supplied text through that branch, a crafted link
  could have run script in the visitor's browser. Now every external string can only
  enter the DOM as inert text — the safe path is the only path.

**Transparency & Legality (copy claims)**
- Header claimed "nothing logged" and the meta description "no tracking." *This page*
  logs nothing, but CARTO, Photon and GitHub Pages see request IPs server-side like any
  web host — a blanket claim we can't make is worse than the modest truth. Both now say
  "no accounts, no analytics," which is provable. The sidebar privacy note already
  describes the three egress paths precisely.

**Accessibility**
- Main-column section heads were `<h3>` under the page's `<h1>` — a skipped heading
  level. Screen-reader users navigate by heading outline, and a skipped level reads as
  a hole in the document. Now `<h2>` (`docs/index.html`, selector updated in
  `styles.css`).

**Info management**
- `docs/README.md` updated to match shipped code (design-system files, self-hosted
  fonts, privacy/CSP section, both test commands, CI). Stale docs actively mislead the
  next reader — truth is the cheapest feature a README has.
- Added `CLAUDE.md`: purpose, the load-bearing constraints (free-only, privacy stance,
  client-side-only, app.R parity, token system), commands, and landmines. This is the
  entry point that keeps a future agent (or human) from optimizing against a
  constraint they couldn't see.
- `.gitignore` now covers `node_modules/` and `.e2e-shots/` so a local playwright
  install can't pollute history.
- Fixed an inaccurate comment in `index.html` (it justified no-referrer with "the URL
  hash can hold an address" — URL fragments are never sent in Referer headers; the
  comment now states the real design).

## Applied at the owner's standing request (behavior-touching, verified)

These change runtime behavior, so they are not Tier 1; they were applied because the
owner asked this session for exactly these properties, and all 71 browser checks + 90
math checks pass with them in place.

- **`referrerPolicy: 'strict-origin'` on the app's own API calls** (`fetchJSON`). The
  page suppresses referrers globally; the OSM services' usage policies ask callers to
  identify themselves, and origin-only does that while leaking nothing (no path, no
  hash — fragments never appear in Referer anyway). Good citizenship toward the free
  services this page depends on.
- **CI** (`.github/workflows/checks.yml`): on every PR and push to main, runs the
  90-check math suite and a drift check — regenerate `docs/data/stations.js` from the
  CSV and fail if it differs. The generated file and its source can no longer silently
  diverge. Runs in under a minute on the free tier.
- **The browser suite moved into the repo** (`tools/e2e_page_test.mjs`, previously
  session-local): 71 checks across all four tabs, keyboard/state/URL behavior, mobile
  overflow, CSP violations, font self-hosting, and fault-injected geocoder/OSRM
  failures. Portable via `PW_MODULE`/`PW_EXECUTABLE`/`BASE` env vars; kept out of CI
  deliberately (browser download ≈ minutes) — run it before UI changes.

## Escalations (Tier 3)

### Escalation: MTA route bullets vs. WCAG contrast
**Plain terms:** The colored subway bullets (white letter on the B/D/F/M orange, G
green) reproduce the MTA's real signage, but that white-on-orange combination measures
about 2.9:1 — below the 4.5:1 guideline for small text. A low-vision reader may find
the letter inside the bullet hard to read. They can still get every piece of
information from the adjacent station and line columns, so nothing is *only* in the
bullet.
**Technical terms:** WCAG 1.4.3 AA wants 4.5:1 for text this size; official MTA hexes
(`#FF6319`, `#6CBE45`) with white ink measure ~2.9:1 and ~2.2:1. Alternatives: dark ink
on those two fills (passes, but contradicts the real-world signage every rider knows),
or non-standard darker fills (breaks the semantic point of using official colors).
**Options:** A — keep authentic MTA colors, information duplicated in text (current
state). B — switch G/B/D/F/M bullets to dark ink. My recommendation: A. The bullets are
supplementary; matching the wayfinding system riders already know is itself an
accessibility property, and the data is never color-alone.

### Escalation: the shareable URL carries the located address
**Plain terms:** After you look up an address, the page's URL remembers it so you can
share the exact view. That's also the one way this tool could leak a location: someone
who shares the link shares the address in it. The sidebar warns about this in plain
words.
**Technical terms:** `#lat/lon/place` live in the URL fragment — never sent to any
server, purely client-side state. Risk is social (pasting the link), not technical.
**Options:** A — keep, with the visible warning (current). B — store coordinates but
drop the human-readable `place` label. C — make URL state opt-in behind a [share]
button. Recommendation: A; B keeps the coordinates anyway (the real information), and C
costs the feature's main convenience. Revisit if the tool gets an audience beyond
people who chose it.

### Escalation: CARTO basemap terms at public scale
**Plain terms:** The map background comes from CARTO's free public tile service.
Free personal/small-project use with attribution is what it's for; if this page ever
gets serious traffic, that generosity has limits.
**Technical terms:** CARTO's free basemaps are offered for non-commercial/light use
with attribution (present, footer + map). No key means no contract; heavy use risks
throttling.
**Options:** A — keep (current; right for a personal tool). B — if traffic grows,
switch the tile URL to another free provider (OSM France, OpenFreeMap) or self-host
PMTiles. One-line change in `app.js`, listed in CLAUDE.md's constraints. Recommendation:
A now, B on evidence of scale.

### Escalation: CSV formula-injection hardening (theoretical)
**Plain terms:** The downloadable CSV contains station names from the MTA's file. If a
future data refresh ever contained a cell starting with `=`, Excel would treat it as a
formula. Today's data has no such cells, and nothing user-typed enters the CSV.
**Technical terms:** Classic CSV injection; mitigations (prefix `'` on `=+-@` starts)
slightly corrupt legitimate data, which is why it isn't applied preemptively.
**Options:** A — leave as-is (data is fixed and clean). B — add the guard to
`downloadReferenceCsv()`. Recommendation: A, with the note in this report serving as
the tripwire if the data source ever changes.

## Scoring notes

**Security & Privacy — 92.** Attack surface is minimal by architecture (no backend, no
storage, no secrets — grep-verified) and the page hardens what remains: CSP pinning
scripts/styles/fonts to self and egress to three named hosts, referrer suppression,
text-only DOM construction with the one unsafe branch now deleted. Egress inventory is
complete and matches the user-facing privacy note. Held below 95 because meta-tag CSP
cannot set `frame-ancestors` (a GitHub Pages limitation — clickjacking framing remains
possible, low stakes for a read-only tool), and the crafted-link `place` label, while
inert, can display misleading text.

**Transparency & Legality — 88.** Point-of-action disclosure is the strength: each
network-touching control explains itself where it sits, and the privacy note enumerates
the exact egress list. Attribution and licenses are complete (OSM/CARTO on-map and in
footer; BSD-2 and OFL texts vendored; MTA credited). The "nothing logged" over-claim —
the classic honest-site trap — is fixed. No accounts, no UGC, no payments means most
legal surface simply doesn't exist. Not higher because I'm not a lawyer and CARTO-terms
comfort rests on common practice, not a contract.

**Accessibility & Inclusivity — 84.** Strong bones: `lang`, skip link, landmarks,
labeled controls, fixed heading order, `aria-pressed`/`aria-live`/`aria-busy`, visible
focus everywhere, reduced-motion support, and every brand text token computationally
verified ≥ 4.5:1. Inclusivity beyond WCAG is genuinely good: free path *is* the product,
187KB critical path respects cheap connections, quick-places give a zero-typing route.
Held down by the open MTA-bullet contrast decision, 34px chips under the 44px touch
guideline, and the honest gap that screen-reader and 320px passes weren't run here.

**Usability — 90.** The zero-network happy path (quick place → all four views populate)
is the design's best decision; async states, double-submit guards, and fault-injected
failure paths all verified. Deliberate friction ([generate heatmap]) is justified by
compute cost and labeled. Held below 95 for the address/origin term split and because
changing travel mode doesn't hint that regeneration is needed until pressed.

**Copy — 88.** Passes the four tests nearly everywhere; buttons say what they do,
errors say what happened and what to do next, and the one absurdism ("argued about at
parties" was cut — the surviving voice is restrained). Over-claims fixed. Held down for
the origin/address inconsistency and a few hints running long.

**Reliability & Performance — 91.** Measured, not vibes: 16ms default raster, 116ms
absolute worst case (493 stations × 81k cells), ~187KB gzipped critical path including
fonts, preconnected tiles, deferred scripts, hard timeouts on every fetch, and every
failure path surfacing visibly (fault-injection tested). No telemetry is a deliberate
privacy trade the owner chose; failures are user-visible by design. Main-thread compute
is fine at these numbers — the Worker is listed as a future candidate, not a gap.

**Info management & Simplicity — 90.** Purpose stated in two sentences in three places,
constraints now recorded where agents look first, docs verified against shipped code,
generated files labeled as generated, vendored code isolated under `vendor/` with
licenses. The 232KB `manifest.json` is shinyapps.io deployment metadata for the R side —
justified, but it is the repo's single heaviest file and worth remembering.

**DevOps — 82.** Deploy = merge (Pages), rollback = `git revert` (static hosting makes
this genuinely instant), CI now gates the math and the data-drift seam, tests are in the
repo and portable. Held down because the browser suite isn't in CI (deliberate, but a
gap), `main` has no branch protection, and Pages setup remains one manual click.
**Process reflection:** (1) The R side's tests print numbers for a human to eyeball
(`test_functions.R`); the JS side's assert — porting that discipline to R would have
caught the alphabetical-sort bug at birth. (2) Until this cycle the repo's two runtimes
shared one artifact (station data) with no guard; the drift check closes the seam where
they'd rot apart. (3) Commit hygiene is good — single-purpose commits with reasons —
keep PRs shaped like that.
